# xmmcode V2：面向零基础学习者的编程游戏设计

日期：2026-08-22
状态：已获用户批准，待实施计划

## 1. 目标

xmmcode V2 要让没有编程经验的学习者能够从“看懂”逐步走到“独立写出”。产品不能把完成关卡等同于复制示例、补一行代码或匹配固定输出，而要证明玩家理解了目标知识点，并能在不同输入下正确使用它。

本次改造覆盖现有 104 个关卡、桌面运行环境、判题系统、提示系统、进度迁移和毕业体验。

### 1.1 成功标准

- 所有正式挑战都从空白编辑器开始，玩家必须输入完整程序。
- 通关前不存在自动填入本题答案的入口。
- 提示能够解释目标、拆解步骤、回忆语法和定位错误，但不替玩家完成题目。
- 普通课程使用隔离的真实 Python，运行结果与标准 Python 保持一致。
- 不适合在本地安全执行的主题使用明确标注的教学实验，不伪装为真实运行。
- 每关执行全部公开与隐藏测试，并在必要时验证目标知识结构。
- 新老玩家都能安全进入 V2，旧 XP、徽章、连续学习和历史完成记录不丢失。

## 2. 当前问题与根因

### 2.1 练习无法证明玩家学会

当前 104 关中有 54 关包含预填代码。部分题目只要求替换 `pass`、补一条表达式或填写几行代码。普通学习页面还提供“参考答案”按钮，可以把标准答案直接写进编辑器。这让玩家能够绕过问题拆解和代码组织。

### 2.2 提示缺少认知台阶

现有提示大多是答案碎片或简短语法提醒。它没有帮助学习者回答以下问题：程序要分成哪几步、每一步为什么存在、当前应该先写什么、错误发生在哪一步。因此学习者即使看完示例和提示，仍不知道如何从空白开始。

### 2.3 判题覆盖不足

课程数据虽然可以声明多个测试用例，运行页面却只执行第一组。判题还会删除所有空白后比较输出，使本应不同的结果可能被当作相同。单纯比较固定输出也无法阻止硬编码答案。

### 2.4 运行环境与 Python 不一致

当前关卡主要由 JavaScript 转译器模拟 Python。SQLite 行格式、线程调度、Socket 字节传输、图表、PySpark 等行为与真实环境不同。项目虽已有桌面 Python IPC，但直接执行系统 Python 既未被课程使用，也不能满足零安装和安全隔离要求。

### 2.5 更新课程会影响旧存档

当前进度仅以章节 ID 和关卡 ID 记录完成状态，没有课程版本和掌握度版本。直接替换题目会让旧玩家显示已完成，却没有经历新版教学流程；直接清空又会损失历史成果。

## 3. 课程体验设计

每个关卡统一为“教学演示 → 分步思考 → 独立挑战”三个阶段。

### 3.1 教学演示：学会看懂

教学演示使用与正式挑战不同的数据，逐行展示：

- 当前执行行；
- 变量名称、类型和值；
- 判断表达式的结果和进入的分支；
- 循环轮次及本轮发生的变化；
- 函数参数、局部变量和返回值；
- 控制台输出产生的时机。

学习者可以单步、继续、重新播放。演示不把代码复制到正式挑战。

### 3.2 分步思考：学会拆解

正式编码前，系统用短问题引导学习者明确：

1. 程序接收或使用什么数据；
2. 需要保存哪些中间结果；
3. 哪一步需要判断、循环、函数或数据容器；
4. 最终应该输出或返回什么。

系统将答案整理为可勾选的任务清单和伪代码。任务清单只描述行为，不包含本题完整 Python 代码。

### 3.3 独立挑战：学会写出

- 编辑器首次进入时为空。
- 课程数据不再向编辑器加载 `starterCode`。
- 学习者必须输入包含数据准备、核心逻辑、调用和输出在内的完整程序。
- 重新挑战和正式复习同样从空白开始。
- 自动保存只保存学习者本人输入的草稿，不保存系统答案或演示代码。

### 3.4 卡住后的退出路径

玩家不能在通关前查看或填入标准答案。如果四层提示仍不足，可进入“完整教学讲解”。讲解会逐步构建一个同类型、不同数据的程序。返回挑战时编辑器重新清空，玩家仍须独立完成原题才能通关。

## 4. 提示与反馈系统

### 4.1 四层提示

1. **目标解释**：用日常语言重述题目，明确输入、处理和输出。
2. **步骤拆解**：给出行为清单和伪代码，指出当前应该完成哪一步。
3. **语法回忆**：展示相关语法模板，但使用不同变量、数据和输出。
4. **代码诊断**：分析玩家当前代码，定位缺失步骤、语法错误或行为错误，并给出下一步行动。

提示不自动修改编辑器，不包含本题完整解法。使用提示不扣基础 XP；系统单独记录“独立完成”“提示后完成”和“教学讲解后完成”。

### 4.2 初学者错误反馈

错误面板同时显示：

- 原始 Python 错误类型和行号；
- 面向初学者的中文解释；
- 与本关任务清单对应的失败步骤；
- 一条明确的下一步建议；
- 实际输出与期望行为的局部差异。

系统不得在一次反馈里列出大量可能原因。优先显示最接近根因、最能继续行动的一条。

### 4.3 反馈示例

对于 `IndentationError`，反馈结构为：

- Python 报错：`IndentationError`，第 4 行；
- 含义：第 4 行应该属于上面的 `for` 循环，但它没有向右缩进；
- 下一步：在第 4 行前添加 4 个空格后重新运行；
- 知识点：缩进表示代码属于哪个代码块。

## 5. 关卡数据模型

课程数据从单一长文本扩展为可验证的教学结构：

```js
{
  id,
  curriculumVersion,
  title,
  learningObjectives,
  prerequisites,
  lessonMode,          // "python" | "visual-lab"
  conceptExplanation,
  demonstration: {
    code,
    traceSteps,
    dataVariant
  },
  planningPrompts,
  checklist,
  syntaxCards,
  challenge: {
    prompt,
    constraints,
    inputDescription,
    outputDescription
  },
  publicTests,
  hiddenTests,
  structuralChecks,
  errorGuidance,
  referenceSolution
}
```

`referenceSolution` 仅用于内容校验、教师维护和自动测试，不能在通关前发送到普通学习界面可访问的状态中。

## 6. 运行架构

### 6.1 执行器边界

课程页面只调用统一接口：

```ts
runLesson({ lessonId, code, inputs }): Promise<RunReport>
```

执行层根据 `lessonMode` 选择：

- `RealPythonRunner`：普通 Python 课程；
- `VisualLabRunner`：线程、Socket、PySpark 和图表实验。

两类执行器返回统一报告：运行状态、标准输出、标准错误、测试结果、结构检查、跟踪事件和可视化数据。

### 6.2 隔离的真实 Python

普通课程使用随应用交付、在 Worker 中隔离的 Python 运行时，优先采用适合 Electron 离线运行的 WebAssembly Python。要求：

- 玩家不需要安装 Python；
- 不访问宿主文件系统；
- 不访问真实网络；
- 每次运行有时间、输出长度和内存限制；
- 文件课程使用每次运行可重置的虚拟文件系统；
- SQLite 使用运行时内的真实 `sqlite3` 语义；
- 运行可被强制终止，死循环不能冻结界面。

不再把直接调用系统 `python3` 作为普通课程的默认路径。

### 6.3 明确标注的教学实验

以下主题不冒充完整真实运行：

- **数据可视化**：Python 生成结构化图表配置，应用真实绘制折线图、柱状图和地图。
- **多线程**：用可视时间线展示任务交错、共享状态和锁；明确说明实验没有创建宿主线程。
- **Socket**：用客户端/服务器双面板展示连接、字节编码、发送、接收和关闭；代码遵循真实 Python 的调用顺序与字节语义。
- **PySpark**：展示 RDD 转换图、惰性执行、分区和 Action；明确说明本地实验未启动 Spark 集群。

每个实验页面固定显示“教学沙箱”标签和“与真实环境的差异”。

## 7. 判题设计

### 7.1 多层验证

每个正式挑战至少执行：

- 公开示例测试；
- 多组隐藏输入测试；
- 运行错误和超时检查；
- 必要的结构检查；
- 对应执行器的安全检查。

所有测试必须执行，不能只运行数组第一项。

### 7.2 输出比较

- 默认仅统一换行符并忽略最后一个无意义换行。
- 不删除字符串内部空格或所有空白。
- 对集合、浮点数或并发顺序等需要特殊比较的题目，使用明确的比较器。
- 失败时显示首个有教学价值的差异，不泄露隐藏测试完整答案。

### 7.3 防止硬编码

隐藏测试使用不同输入和值。对于目标知识点明确的课程，使用 Python AST 进行最小结构验证，例如：

- 循环课程要求存在合适的循环结构；
- 函数课程要求定义并调用函数；
- 异常课程要求包含相应异常处理；
- 类课程要求创建类并实例化。

结构检查只验证学习目标，不限制变量名称、格式或合理替代解法。

## 8. 内容改造规则

现有 104 关全部按统一清单审校：

- 删除预填 `starterCode`；
- 删除“补全下面一行”“把 pass 换成”等描述；
- 将示例与挑战使用的数据分开；
- 为每关补齐学习目标、规划问题、任务清单、四层提示和错误指导；
- 至少加入两类有效测试数据；
- 修正标准答案与真实 Python 的差异；
- 检查前置知识，避免题目跨越尚未教授的概念；
- 每章结束增加一个综合小项目；
- 增加读代码、预测输出和找错练习，但正式写代码挑战仍从空白开始。

优先重写已知高风险章节：SQLite、数据可视化、多线程、Socket、PySpark、文件和异常处理。

## 9. 进度、掌握度与迁移

### 9.1 数据版本

进度数据增加：

- `curriculumVersion`；
- `lessonContentVersion`；
- 完成方式；
- 提示使用层级；
- 失败类型统计；
- 最近一次掌握度评估。

### 9.2 旧存档迁移

- 原 XP、徽章、连续学习和完成记录保存在历史档案。
- 首次进入 V2 时提供“保留当前完成状态”和“从第一关开始新版学习”。
- 重新学习创建独立 V2 进度，不删除旧档。
- 玩家可在设置中查看历史档案和切换当前课程档案。
- 迁移操作可撤销，导入导出同时包含历史档和 V2 档。

## 10. 游戏化与学习闭环

- 提示不扣基础 XP，避免惩罚求助行为。
- “独立完成”作为额外掌握标记和成就条件。
- 复习依据错误类型和掌握度安排，而非只按日期重复同一道题。
- 知识地图显示已掌握、正在学习、需要复习和前置知识。
- 每章项目组合本章多个知识点，不允许直接复制单关答案。
- 最后一关后展示毕业页面：掌握知识、薄弱点、项目作品和后续建议。
- 徽章与总关卡数通过课程数据动态计算，不能写死阈值。

## 11. 可访问性与新手引导

- 初次进入询问学习目标、已有经验和每日可投入时间。
- 支持字体缩放、键盘完整操作、减少动画和色盲友好配色。
- 代码编辑器提供明确焦点状态、快捷键说明和可读的错误标记。
- 新手引导必须允许跳过，也能从设置重新打开。
- 中文为主要教学语言，关键 Python 术语保留英文并解释含义。

## 12. 实施边界与阶段

### 阶段 A：可信练习基础

- 清空全部预填代码；
- 移除通关前参考答案；
- 执行全部测试并修复空白比较；
- 增加统一课程数据校验；
- 修复徽章阈值和最终毕业流；
- 加入课程版本和无损迁移基础。

### 阶段 B：三阶段教学与提示

- 建立教学演示、分步思考和独立挑战页面；
- 实现任务清单、四层提示和初学者错误反馈；
- 先完整改造第一章作为质量基线；
- 通过可用性测试后批量改造剩余课程。

### 阶段 C：真实 Python 与教学实验

- 接入隔离 Python Worker；
- 迁移核心课程和 SQLite；
- 实现图表、多线程、Socket、PySpark 教学实验；
- 删除普通课程对旧 JavaScript Python 模拟器的依赖。

### 阶段 D：104 关内容重写与学习闭环

- 按章节逐关重写并补齐测试；
- 增加章末项目、读代码、预测和调试练习；
- 接入掌握度复习、知识地图和毕业总结；
- 完成全量桌面回归测试。

## 13. 错误处理与安全要求

- 运行超时、运行时崩溃和 Worker 失联必须恢复为可再次运行的状态。
- 运行按钮在执行期间防止重复提交，并提供停止按钮。
- 玩家代码、输入和错误信息不得发送到外部服务，除非玩家主动使用并明确同意 AI 助手。
- AI 助手默认采用苏格拉底式引导，不提供本题完整答案，不直接写入编辑器。
- 存档迁移前自动创建可导出的备份；迁移失败时回滚到原数据。

## 14. 测试与验收

### 14.1 自动化测试

- 课程 schema 和唯一 ID 校验；
- 104 关 `starterCode` 均为空或字段被移除；
- 标准答案通过全部公开与隐藏测试；
- 代表性硬编码、错误结构和边界输入被拒绝；
- Python 输出与基准运行时一致；
- 超时、输出过长、语法错误和 Worker 重启测试；
- 进度迁移、回滚、导入和导出测试；
- 章节解锁、XP、徽章和毕业状态测试。

### 14.2 桌面端到端测试

- 新玩家从零完成代表性课程；
- 老玩家迁移后历史数据完整；
- 三阶段流程可仅用键盘完成；
- 使用每层提示仍不会自动得到或填入答案；
- macOS 与 Windows 在未安装系统 Python 时可运行核心课程；
- 104 关能够按顺序解锁并完成最终毕业。

### 14.3 内容质量抽检

每关必须由审校清单证明：

- 示例没有直接复用挑战答案；
- 题目只依赖已经教授的知识；
- 提示从思路逐层深入且没有泄露完整解法；
- 错误反馈能指向一个明确行动；
- 隐藏测试覆盖至少一个边界或替代输入；
- 复制固定输出不能通关；
- 初学者能够解释程序每个主要步骤的作用。

## 15. 非目标

- V2 首轮不构建在线多人、排行榜、云账户或教师管理后台。
- 教学实验不承诺提供真实 Spark 集群或开放本机网络端口。
- 不以一次性重写视觉主题代替教学与判题改造。
- 不删除用户已有存档或强制旧玩家重新学习。

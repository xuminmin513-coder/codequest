# XM²code iOS 极简 UI 统一改版设计

日期：2026-08-27
状态：视觉方案已获用户批准，等待书面规范复核

## 1. 目标

本次改版把现有 XM²code 界面统一为适合网页与 PWA 的 iOS 极简视觉，并解决学习页空间局促、测试结果与运行输出割裂、品牌显示不一致和存档入口复杂的问题。

成功标准：

- 全站统一使用 `XM²code` 品牌名，方形品牌标记和右上角玩家标识均显示 `XM²`。
- 不使用狐狸、动物吉祥物或与“小狐狸讲代码”相似的品牌元素。
- 桌面端核心区域充分使用窗口空间；挑战页不再在底部留下大面积无意义空白。
- 测试结果和运行输出位于同一个浅色结果抽屉中，通过标签切换，不再使用并排的浅色测试框和大块深色输出框。
- 所有现有页面获得统一的字体、圆角、间距、边框、按钮、状态颜色和响应式规则。
- 手机、平板和电脑浏览器都能清楚完成导航、阅读题目、输入代码、运行测试和查看结果。
- 原有通关礼花、课程进度、复习规则、存档和判题行为保持可用。

## 2. 本次范围

采用已确认的“完整统一改版”范围，覆盖：

- 应用外壳、品牌区、侧栏和移动端导航；
- 学习首页；
- 课程地图；
- 课程与挑战页面；
- 复习计划；
- 成就与毕业页面；
- 设置、快捷键和迁移对话框；
- 单存档槽和添加存档入口；
- Toast、徽章弹窗、技能解锁弹窗和通关礼花的视觉统一。

本次不包括：

- AI 代码翻译或在线 AI 助手；
- 登录、云同步和支付；
- 应用商店外壳及各操作系统安装包；
- 新课程内容、动画播放器和理解题业务逻辑的开发；
- 修改判题规则或 Python 安全运行边界。

若某个已讨论的学习阶段尚未实现，本次只为现有真实功能提供合适布局，不显示会误导玩家的假按钮或假进度。

## 3. 视觉语言

### 3.1 品牌

- 产品名统一写作 `XM²code`，使用真正的上标平方符号 `²`。
- 品牌方形标记显示 `XM²`，文字水平和垂直居中。
- 右上角玩家标识显示 `XM²`，作为中性玩家入口，不使用狐狸图标。
- 中文和英文界面均保持同一品牌拼写。

### 3.2 字体与层级

- 界面字体优先使用系统字体：Apple 平台使用 San Francisco，其他平台回退到对应系统无衬线字体。
- 代码使用系统等宽字体。
- 页面只保留明确的四级层级：页面标题、卡片标题、正文、辅助信息。
- 正文保持足够字号和行高，不使用为了“显得精致”而过小的文字。

### 3.3 颜色

基础颜色：

- 页面背景：浅灰蓝；
- 内容卡片：白色；
- 主文字：深蓝灰；
- 次文字：中性灰蓝；
- 主操作：清晰但不过度饱和的蓝色；
- 边框：低对比浅灰蓝。

状态颜色只用于表达状态：

- 通过：低饱和绿色；
- 失败：低饱和红色；
- 修复建议：柔和橙色；
- 等待或普通信息：中性浅灰蓝。

测试结果和运行输出不得分别使用完全不同的明暗主题。代码编辑器可以保留深色，因为它是持续编辑的独立工作区；结果区域统一为浅色，减少视觉割裂。

### 3.4 形状与动效

- 页面卡片采用 16–24 像素圆角，控件采用 8–14 像素圆角。
- 阴影只用于页面级容器、浮层和当前交互卡片，避免每个元素都悬浮。
- 动效以 150–250 毫秒的淡入、位移和状态过渡为主。
- 通关后保留礼花特效；同时保留文字成功反馈，不能只依赖动画传达通关。
- 遵守系统“减少动态效果”设置，关闭非必要位移和粒子动画。

## 4. 应用外壳与导航

### 4.1 桌面端

- 左侧固定导航宽度约 220–240 像素。
- 顶部显示 `XM²` 方形标记和 `XM²code` 名称。
- 导航项目使用简洁线性图标与文字；当前页面采用浅蓝选中背景。
- 侧栏底部展示等级、XP 或待复习信息，以及语言切换。
- 主内容区根据窗口宽度伸展，并设置合理的最大阅读宽度；挑战工作台不使用普通页面的窄内容宽度。

### 4.2 移动端

- 侧栏折叠为顶部品牌栏和底部主导航。
- 底部只保留最常用入口，其他入口收纳到“更多”。
- 所有按钮至少拥有 44×44 像素触控区域。
- 不依赖悬停才能发现功能。

## 5. 页面布局

### 5.1 学习首页

- 首屏优先显示“继续学习”主卡片，而不是大量统计数字。
- 今日复习、连续学习和总体进度作为次级卡片。
- 页面只保留一个主要蓝色行动按钮。
- 统计信息使用中性卡片，不用高饱和彩色方块堆叠。

### 5.2 课程地图

- 每章使用清晰的章节卡片和纵向学习路径。
- 已完成、当前、可进入和锁定状态同时通过图标、文字和颜色表达。
- 课程卡片显示标题、学习目标、关卡数量和进度，不在同一区域堆叠过多徽章。

### 5.3 复习、成就、设置和其他页面

- 使用同一页面标题区和同一卡片系统。
- 复习页突出“现在应该复习什么”和下一次复习时间。
- 成就页降低未解锁项目的对比度，但仍显示明确解锁条件。
- 设置页按“学习体验、数据与存档、语言、关于”分组。
- 危险操作与普通设置分离，并使用明确确认对话框。

## 6. 课程与挑战工作台

### 6.1 顶部

- 顶部显示返回课程、章节与关卡名称、保存状态和 `XM²` 玩家标识。
- 若课程阶段功能已经真实存在，显示阶段导航；尚未实现的阶段不显示为可交互项。

### 6.2 桌面布局

挑战页面使用完整可用高度：

- 左侧约 25%：题目、目标、完成清单、输入输出要求和分层提示；
- 右侧约 75%：代码编辑器；
- 右侧底部：统一结果抽屉；
- 窗口增高时优先增加编辑器高度，不留下大面积空白。

左侧题目区可独立滚动。提示默认收起，按需逐层打开；提示不会修改编辑器，也不展示本题完整答案。

### 6.3 手机布局

- 题目区变成可展开的“题目”抽屉。
- 编辑器占据主要屏幕高度。
- 运行按钮保持固定可见，但不能遮挡代码。
- 结果抽屉出现在编辑器下方，可在测试和输出之间切换。
- 为常用代码符号预留触控快捷栏位置，但不在本次 UI 改造中改变编辑器输入逻辑。

## 7. 测试结果与运行输出

采用用户最终确认的统一浅色结果抽屉：

- 顶部使用分段标签：“测试结果”和“运行输出”。
- 两个标签共享浅灰蓝容器、白色内容卡片、同一边框和文字层级。
- 测试标签显示通过数量、运行耗时和最重要的一条失败原因。
- 单项测试使用中性白卡；通过和失败只在状态圆点、状态文字和局部提示中着色。
- 输出标签使用浅色等宽文本区域，不恢复大块黑色终端背景。
- 运行错误展示错误位置、简明解释和一条下一步建议。
- 隐藏测试不得泄露完整答案。
- 窄屏只显示一个标签的内容，不横向挤压两列结果。

## 8. 存档界面

- 默认只显示一个存档槽。
- 存档槽显示玩家名称、课程进度、XP、最近保存时间和“继续学习”。
- 存档槽旁边显示虚线“添加存档”按钮；玩家主动点击后才创建新槽。
- 彩色头像方框中的文字必须严格水平、垂直居中。
- 存档历史和恢复入口作为次级操作，不与“继续学习”争夺视觉焦点。
- 本次只改视觉和现有操作入口，不新增登录或云存档。

## 9. 组件边界

为了避免把整套 UI 继续堆进单个样式文件，实施时按以下边界组织：

- `AppShell`：桌面侧栏、移动导航和主内容容器；
- `BrandMark`：统一渲染 `XM²` 和 `XM²code`；
- `PageHeader`：页面标题、说明和可选操作；
- `Surface` / `StatCard`：通用卡片与统计卡片；
- `LessonWorkspace`：题目区、编辑器区和结果区布局；
- `LessonResultDrawer`：测试与输出标签及状态呈现；
- `SaveSlotCard`：单个存档槽和添加入口；
- `StatusBadge`：等待、通过、失败和提示状态。

组件只接收显示所需的数据和回调，不直接复制存储、判题或运行逻辑。现有业务逻辑继续留在当前上下文、存储和运行层中。

## 10. 可访问性与国际化

- 文字和背景满足 WCAG AA 对比度目标。
- 颜色之外始终提供图标或文字状态。
- 键盘可访问所有按钮、标签、对话框和导航入口。
- 焦点样式清楚可见。
- 标签切换使用正确的 tab 语义；错误信息可被屏幕阅读器感知。
- 中英文长度差异不能造成按钮截断或布局重叠。
- 视觉组件不硬编码中文，继续使用现有语言状态。

## 11. 数据流与错误处理

- UI 改版不改变课程、存档、复习和判题数据格式。
- 运行按钮继续调用现有安全 Python Runner；停止、超时和输出过量仍沿用现有保护。
- 结果抽屉只负责展示统一的运行报告，不自行判断通关。
- 存档读取失败、运行环境失败或课程迁移失败时，在对应页面展示可行动的错误说明，并保留 Toast 作为辅助通知。
- 界面不能因为空数据、长标题、长错误信息或英文文案而溢出或崩溃。

## 12. 测试与验收

实施采用测试驱动方式：先为新组件和关键交互编写失败测试，再实现视觉与行为。

自动化验收至少覆盖：

- 全站只使用 `XM²code` / `XM²` 品牌，不出现旧 `xmmcode` 或狐狸标识；
- 桌面和移动导航可访问；
- 挑战工作台在桌面宽度下形成题目、编辑器、结果抽屉结构；
- 测试结果与运行输出使用标签切换，且不出现旧的深色输出大框；
- 运行、停止、通关、礼花和下一关功能不回归；
- 默认一个存档槽，并存在添加存档入口；
- 中英文文案均不导致明显溢出；
- 键盘焦点和对话框语义正确；
- 现有单元测试、课程校验、生产构建和端到端安全测试全部通过。

视觉验收使用桌面、平板和手机三个视口截图，检查：

- 信息层级和留白；
- 颜色一致性；
- 挑战页面空间利用；
- 长文案、错误状态和成功状态；
- 触控按钮大小；
- 礼花不会遮挡必须操作的按钮。

## 13. 已确认决策

- 采用 iOS 极简风格。
- 采用完整统一改版范围。
- 品牌为 `XM²code`，标记为 `XM²`。
- 不使用狐狸标识。
- 默认一个存档槽，旁边提供添加存档按钮。
- 挑战工作台充分使用窗口空间。
- 测试结果和运行输出合并为统一浅色结果抽屉。
- 通关后继续保留礼花特效。
- 当前不恢复 AI 代码翻译功能。
- 优先服务网页版与 PWA，不为应用商店外壳定制 UI。

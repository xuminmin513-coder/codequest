# Python 运行环境预热与学习状态安全设计

日期：2026-08-30

## 目标

在继续使用真实 Python（Pyodide）的前提下，解决课程页每次运行都重新启动 Python、编辑器内容在运行状态变化时丢失、草稿没有真正自动保存，以及同次通关多个徽章只保存最后一个的问题。

本次改动的核心体验目标是：进入关卡时后台准备一次 Python；同一关卡后续运行接近即时响应；运行、停止、报错、切换结果标签和保存状态变化均不得清空玩家代码。

## 已确认方案

采用“进入关卡时预热，每个关卡复用一个隔离 Worker”的方案。

没有采用以下方案：

- 首次点击运行时才加载：实现较简单，但玩家仍会在最需要反馈时等待约 2～3 秒。
- 恢复旧版 JavaScript Python 模拟器：速度快，但只支持部分语法，可能产生与真实 Python 不一致的教学结果。

## 范围

本次包含：

1. Python Worker 的显式预热、就绪握手、复用、停止、超时和崩溃恢复。
2. 课程页对运行环境的关卡级生命周期管理。
3. 编辑器实例稳定、快捷键回调更新和关卡草稿自动保存。
4. 通关存储顺序、批量徽章保存和多徽章展示队列。
5. 针对以上行为的单元、契约和浏览器端验收测试。

本次不包含：

- 更换 Python 版本或重新启用模拟执行。
- 重写课程、判题标准、提示内容或关卡顺序。
- AI 代码翻译、账号、云同步或跨设备存档。
- 重构整套存档格式或修改现有存档键名。
- 为了本次优化引入服务器或在线运行服务。

## 运行架构

### `PythonRunner`

`createPythonRunner()` 增加显式的 `prepare()` 能力，并继续提供 `run()`、`stop()` 和 `dispose()`：

- `prepare()` 只创建一个 Worker，并等待 Worker 返回可信的就绪消息。
- 多次调用 `prepare()` 共用同一个进行中的 Promise，不重复创建 Worker。
- `run()` 在环境未就绪时等待同一个预热任务；只有收到就绪消息后才开始计算代码执行超时。
- 同一时刻只允许一个判题执行。重复点击不会排队或创建第二个环境。
- `stop()`、执行超时或 Worker 崩溃会结束当前任务并销毁 Worker。
- 被销毁但尚未 `dispose()` 的运行器可重新 `prepare()`，供课程页自动恢复。
- `dispose()` 永久结束运行器，清理计时器、事件监听器和 Worker；此后不再自动重建。

运行器维护明确状态：`idle`、`preparing`、`ready`、`running`、`recovering`、`failed`、`disposed`。组件只消费状态和结果，不直接管理 Worker 事件。

### Python Worker

Worker 模块加载后立即初始化 Pyodide，初始化成功后发送带协议版本的 `ready` 消息，失败时发送有界长度的初始化错误。

每次执行继续使用独立的 Python 全局字典，并在执行前后恢复以下学习环境：

- 清理 `/home/pyodide` 中玩家创建的临时文件；
- 重置标准输入、标准输出和标准错误；
- 重置当前工作目录；
- 为执行设置新的 `__main__` 全局空间；
- 销毁本次运行创建的 PyProxy。

变量、输入、输出、工作目录和临时文件不得从一次运行泄漏到下一次运行。标准库本身可由同一 Pyodide 实例复用，以保留预热带来的速度收益。

### 课程页生命周期

课程页为当前关卡持有一个运行器：

1. 找到并验证关卡后立即创建运行器并调用 `prepare()`。
2. 玩家在预热期间仍可编辑代码。
3. 玩家在预热完成前点击运行时，当前运行请求等待预热完成后自动继续，无需再次点击。
4. 同一关卡的所有测试用例顺序使用同一运行器；每个测试用例仍有干净的执行空间。
5. 停止、超时或崩溃后显示本次结果，并在后台创建干净 Worker 重新预热。
6. 切换关卡或卸载课程页时取消旧任务并 `dispose()`，旧关卡结果不得写入新关卡界面。

预热失败时保留编辑器和草稿，界面提供“重新准备”操作。失败不会被伪装成玩家代码错误。

## 超时与错误

初始化超时和执行超时分别计算：

- 初始化计时从创建 Worker 开始，到收到就绪或初始化失败消息结束。
- 代码执行计时只从 Worker 确认可以执行后开始。
- 初始化较慢不得被报告为“代码执行超时”。
- 执行超时和主动停止通过终止 Worker 保证死循环确实结束；随后自动预热新 Worker。
- 运行时 Python 错误不必销毁健康 Worker，但必须完成执行环境清理。

用户界面区分“正在准备 Python”“正在运行”“运行已停止”“运行环境准备失败”和真实 Python 报错。面向初学者的简短说明与原始 Python 错误同时保留。

## 编辑器与草稿

`CodeEditor` 的实例生命周期只由编辑器容器和关卡身份决定，不再依赖 `onRun` 函数身份。运行与停止回调通过稳定引用读取当前函数，防止 `isRunning` 改变时销毁并重建 CodeMirror。

编辑器需报告内容变化，课程页按以下规则保存：

- 普通学习模式下，停止输入 400 毫秒后调用现有 `STORAGE.saveCode(lessonId, code)`。
- 切换关卡或卸载前立即刷新尚未写入的草稿。
- 复习模式不覆盖普通关卡草稿，并继续遵守现有复习清理规则。
- 进入普通关卡时恢复对应关卡草稿；不同关卡互不覆盖。
- 通关存储完成后才清除该关卡草稿。
- 存储失败时保留编辑器内容和内存中的待保存草稿，显示简短提示，但不打断编辑和运行。

运行、停止、预热、报错、结果标签变化和提示展开均必须保留文档内容、选区、光标位置和编辑器滚动位置。

## 运行按钮与结果状态

运行按钮继续位于黑色编辑器内部右下方：

- 预热中显示“正在准备”，玩家点击后记录一次待执行意图；就绪后自动执行。
- 就绪时显示“运行代码”。
- 执行中在同一位置显示“停止”，尺寸和布局不跳动。
- 恢复中显示“正在恢复”，避免玩家连续创建运行环境。
- 失败时显示“重新准备”。

结果抽屉继续保留“运行输出”和“测试结果”，但状态信息必须说明当前阶段，不能把环境加载时间显示成玩家代码耗时。

## 通关存储与徽章

通关处理集中为一个可重试、幂等的流程：

1. 读取当前进度、连胜、复习计划、完美通关记录和徽章。
2. 计算一次完整的下一状态。
3. 按确定顺序写入现有存储键。
4. 全部必要写入成功后，才更新页面为“已完成”、清除草稿并显示成功反馈。

本次不迁移到新的单对象存档格式，因此浏览器 `localStorage` 不能提供跨键数据库事务。为避免部分写入造成重复奖励，所有更新必须幂等：再次执行只补齐缺失状态，不重复增加 XP、连续天数、复习次数或徽章。

同次满足多个徽章时：

- 把旧徽章与所有新徽章去重合并后只调用一次 `saveBadges()`；
- 使用徽章展示队列依次显示每个新徽章，而不是循环覆盖同一个弹窗状态；
- 礼花与徽章弹窗只负责视觉反馈，不阻塞存档、测试结果或下一关导航。

写入失败时不显示虚假的“已保存”。玩家代码继续保留，并可重新触发安全的幂等保存流程。

## 数据流

一次正常运行的数据流如下：

1. 课程页加载关卡并恢复草稿，同时调用运行器 `prepare()`。
2. Worker 初始化 Pyodide 并返回 `ready`。
3. 玩家点击运行，课程页从稳定的编辑器实例读取当前代码。
4. `judgeLesson` 顺序提交测试用例；运行器校验请求并发送给同一 Worker。
5. Worker 为每个用例创建干净执行空间，返回经过协议校验的结果。
6. 当前关卡的运行令牌仍有效时，课程页更新结果抽屉；过期结果被丢弃。
7. 通过后执行幂等通关存储，成功后显示礼花、徽章队列和下一关操作。

## 测试设计

实施采用测试优先方式，先增加能在当前实现上失败的测试。

### 运行器单元测试

- `prepare()` 的并发调用只创建一个 Worker。
- `run()` 在预热完成前等待，不重复创建 Worker。
- 初始化计时与执行计时分离。
- 同一健康 Worker 可连续执行多个请求。
- 重复并发运行被安全拒绝。
- 停止、执行超时和崩溃会终止 Worker，之后可重新预热。
- `dispose()` 后不能重建。
- 过期、错误协议版本和能力标识不匹配的消息被忽略。

### Worker 隔离测试

- 连续运行之间不共享普通变量。
- 输入和输出缓冲不串用。
- 玩家临时文件和当前工作目录被重置。
- Python 异常后下一次运行仍处于干净状态。
- 输出限制和请求大小限制保持有效。

### 编辑器与课程页测试

- 运行状态切换不会重新创建编辑器 DOM。
- 代码、光标、选区和滚动位置在运行与停止后保持不变。
- 快捷键始终调用当前的运行或停止行为。
- 草稿按关卡保存并恢复，复习模式不覆盖普通草稿。
- 切换关卡前刷新待保存草稿，旧运行结果不能进入新关卡。
- 预热、运行、恢复和失败状态显示正确按钮文案。

### 存储与奖励测试

- 通关保存失败时不清除草稿、不显示已保存状态。
- 重试部分完成的通关写入不会重复 XP、连胜或复习计划。
- 同次获得多个徽章时全部去重保存，且弹窗按队列逐个展示。
- 礼花不会延迟保存和下一关操作。

### 集成与性能验收

- 使用真实 Pyodide 完成进入关卡、首次运行、再次运行、报错、停止、恢复和通关流程。
- 记录预热耗时与纯执行耗时，确认第二次运行不再承担 Pyodide 冷启动成本。
- 性能自动测试不设置容易受机器负载影响的绝对毫秒硬门槛；以“同一关卡只初始化一次”和“后续运行不重新创建 Worker”为稳定门槛，并在人工验收中记录实际耗时。
- 运行完整单元测试、课程审计、构建、安全检查和浏览器端核心流程测试。

## 完成标准

- 同一关卡只初始化一次 Python，正常后续运行不重新创建 Worker。
- 首次预热不会被误判为玩家代码超时。
- 停止、超时或崩溃后无需刷新页面即可再次运行。
- 运行或停止不再清空代码，光标和滚动位置不跳动。
- 普通关卡草稿能够自动保存、刷新后恢复，并且按关卡隔离。
- 多个新徽章全部保存且逐个展示。
- 存储失败不产生虚假成功提示，重试不重复奖励。
- 真实 Python、离线执行、Worker 隔离、协议校验和现有安全边界全部保留。
- 所有相关自动测试和实际完整流程验收通过。
